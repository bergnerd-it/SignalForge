## Remaining findings (original IDs)

| ID | Classification, evidence and impact | Closeout remedy |
|---|---|---|
| **HIGH-3 — frozen intent and replay** | **Verified defect.** `canonicalHash()` includes request fields only ([BacktestDtos.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestDtos.java#L89), lines 89–125), and creation checks that hash before building the frozen dataset/engine snapshot ([BacktestJobService.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestJobService.java#L79), lines 79–100, 127–181). The same owner/key/request can therefore return a historical run after engine or dataset identity changes, contrary to M3's obsolete-engine replay rule. Source commit and `dirtyFlag=true` are hard-coded at lines 176–178, so future builds can be mislabeled. The repeated-run test compares metrics/events under one binary (BacktestIntegrationTest.java:729–802), not replay across version/identity changes. | Derive build identity from the actual build, freeze the complete resolved configuration, and bind the idempotency identity to the relevant frozen engine/dataset/version fields. Test same-key behavior when an identity changes and verify the manifest reflects the stored snapshot. |
| **MEDIUM-1 — funding/day counts/annual labels** | **Verified defect.** The initial funded equity point is still dated to the evaluation session even though the funding event is placed before the next execution open ([BacktestEngine.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestEngine.java#L111), lines 111–129, 149–168). CAGR starts at the first equity point, so it counts the evaluation-to-execution gap ([BacktestAnalyticsCalculator.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestAnalyticsCalculator.java#L30), lines 30–39). Partial-year detection remains a Jan 7/Dec 24 heuristic (lines 235–240), not the actual calendar/reporting interval. This can change reported annualization and year labels. | Represent initial funded equity at the actual first-execution boundary without adding a false trading-day return; compute elapsed days and partial years from the effective reporting interval/calendar. Add a long-period fixture where evaluation and first execution differ, plus holiday/year-boundary cases. |
| **HIGH-5 — complete chart series** | **Verified defect.** `fetchAllEquity()` stops when accumulated rows reach 50,000 even if the API still says `hasMore=true`; it returns the partial array as a complete series ([backtest.service.ts](../../frontend/src/app/services/backtest.service.ts#L134), lines 134–150). The backend has a per-page cap, not a matching total-run cap (BacktestJobService.java:617–656). The frontend test exercises two tiny pages, not this boundary (services.spec.ts:663–734). | Continue to the end or show an explicit incomplete-series state with total/loaded counts. Test the exact cap and the `hasMore=true` boundary. |
| **MEDIUM-3 — bounded export response** | **Verified defect.** Row-count checks moved ahead of ZIP writing but remain inside `streamExportZip()`, called from `StreamingResponseBody` after the controller has returned a 200 ZIP response ([BacktestController.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestController.java#L96), lines 96–115; [BacktestExportService.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestExportService.java#L40), lines 40–68). An over-limit export cannot reliably produce the promised clean pre-response error. No output-byte bound is enforced. The error message also reports the 100,000-row series limit even when only the 10,000-row holdings limit was exceeded. | Validate all limits before constructing the streaming response; enforce/document a practical byte bound or a proven creation-time bound. Add exact-boundary and over-limit HTTP/download tests, including holdings. |
| **HIGH-4 — race/rollback evidence** | **Missing evidence, not a proven defect.** The new same-key test is concurrent, but the queued-cancel test inserts a row directly without an actual queued worker, and repeat-cancel tests only a COMPLETED row despite their title (BacktestIntegrationTest.java:653–727). No barrier-controlled cancellation/completion race, queue-full rejection, or injected publication-rollback case is present. The transaction code may be correct; the M3 gate is not established by the current suite. | Add focused temporary-SQLite tests for the real queued task, repeat CANCELLED, cancellation/publication interleaving, full queue, and forced failure after partial child inserts; assert terminal status and zero published partial results. |
