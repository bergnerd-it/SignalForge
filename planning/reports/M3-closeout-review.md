# Independent M3 closeout review

Date: 2026-09-13. **Recommendation: do not close M3 yet.** Several native M3 requirements remain demonstrably unmet. Docker remains explicitly deferred and is not a blocker in this verdict. This review covers the original IDs in [M3-code-review.md](M3-code-review.md); [research-M3-fixes.md](research-M3-fixes.md) and [walkthrough-m3-fixes.md](walkthrough-m3-fixes.md) remap several of those IDs and overstate completion.

| **CRITICAL-1 — owner scope and SQL injection** | **Partly fixed; verified defect remains.** Every exposed run route passes `X-User-Id` to an owner-scoped parent lookup, including export before response creation ([BacktestController.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestController.java#L23), lines 23–116; [BacktestJobService.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestJobService.java#L461), lines 461–510). Equity/orders/events parse `SeriesType` and bind it; the integration test checks cross-owner detail/equity/orders/events/export/cancel and malicious series (BacktestIntegrationTest.java:265–285). But the internal bars and actions reader still inserts listing IDs into `IN ('...')` SQL text ([BacktestDataReader.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestDataReader.java#L351), lines 351–355, 392–397). Those IDs come from imported dataset records, so the remaining injection surface is lower trust than a direct `series` request but still violates parameterized SQL and can change the query or fail a run. Bind both listing IDs in both queries; add a malicious imported-ID integration case. No cross-owner read/cancel leak was found in the exposed routes. |
| **HIGH-1 — interval/month-end/cutoff** | **Partly fixed; verified defect remains.** The reader now parses dates/instants, requires a trading month-end start and explicit trading end ([BacktestDataReader.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestDataReader.java#L192), lines 192–240, 256–283). It compares cutoff only with evaluation session **close**, not with either required evaluation bar's `available_at`; the bar-presence loop covers only run sessions, not the evaluation session (lines 228–240, 374–384). A cutoff after close but before bar publication is therefore accepted, and a missing evaluation bar becomes a Day-0 zero raw close in [BacktestEngine.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestEngine.java#L90), lines 90–107. Require both evaluation observations, compare their availability instants to cutoff, and test the gap. |
| **HIGH-2 — corporate actions/payment** | **Partly fixed; verified defects remain.** EUR/positive distribution and non-null run-window action availability checks exist ([BacktestDataReader.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestDataReader.java#L418), lines 418–453). The engine has pre-open, intraday and date-only/closed-day settlement branches (BacktestEngine.java:223–305, 389–444), but `paymentDate` and `paymentInstant` may both be null: validation does not reject that case, so a booked receivable can remain forever without a defined payment boundary. The entitlement event preserves only `paymentDate`, not `paymentInstant` or entitlement timestamp ([BacktestEngine.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestEngine.java#L181), lines 181–217); final holdings store only aggregate positions ([BacktestJobService.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestJobService.java#L450), lines 450–458). Known unpaid receivables are thus not individually reproducible from persisted results. `splitRatio()` rounds every rational to 8 decimals rather than rejecting an unrepresentable ratio ([BacktestDataReader.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestDataReader.java#L61), lines 61–66). Reject missing timing, persist each outstanding action/amount/entitlement/payment instant, and reject unsupported split precision before applying it; exercise precise, closed-day and beyond-end payments. |
| **HIGH-3 — frozen config/deterministic replay** | **Partly fixed; verified defects remain.** Ordered event/order IDs now derive from run ID, series and sequence, and most business times derive from sessions. The stored config has dataset checksums and versions, but omits strategy ID/version, calendar timezone and coverage, retains raw rather than normalized numeric request strings, and hard-codes source commit `855b9498...` and `dirtyFlag=false` although this source is `a13a5ad...` with uncommitted fixes ([BacktestDtos.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestDtos.java#L132), lines 132–161; [BacktestJobService.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestJobService.java#L141), lines 141–170). `canonicalHash()` is calculated before the preflight snapshot and therefore cannot bind those identities (BacktestJobService.java:78, 126–170). Export reconstructs a manifest from config plus run fields, with fallback on parse failure, rather than exporting the stored snapshot verbatim ([BacktestExportService.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestExportService.java#L57), lines 57–115). Split/entitlement events use fixed `08:55Z` (BacktestEngine.java:159, 201), which can be later than a calendar open such as `08:00Z`; sequence then contradicts timestamps. Complete and freeze the specified identity, bind replay to it, and derive pre-open event times from each session. Add repeated-run comparisons of financial output and ordered business events after excluding run IDs/operational timestamps. |
| **HIGH-4 — idempotency/cancel/races** | **Improved; remaining behavior is unverified.** Unique owner/key constraint, conflict recovery, terminal repeat-cancel no-op, conditional cancel and completion, bounded 50-job queue, startup interruption query, and transactional child publication are present ([BacktestJobService.java](../../backend/src/main/java/com/bergnerd/signalforge/app/research/backtest/BacktestJobService.java#L34), lines 34–55, 80–99, 179–226, 335–370, 472–499). The three backtest integration tests cover sequential replay/conflict and one manually inserted RUNNING restart row, not concurrent same-key creation, queued/repeat cancellation, cancellation versus completion, queue rejection, injected publication rollback, or QUEUED restart ([BacktestIntegrationTest.java](../../backend/src/test/java/com/bergnerd/signalforge/app/research/backtest/BacktestIntegrationTest.java#L180), lines 180–207, 346–382). The transaction code supports rollback, but the race outcome is **missing evidence**, not proven correct or broken. Add barrier-driven temporary-SQLite tests for these exact gates and a bounded SQLite reservation retry where needed. |
| **HIGH-5 — frontend completeness/stale responses** | **Partly fixed; verified defects remain.** Both series are requested and deep links resolve by ID. The service asks for one `limit=10000` page per series, but the backend caps equity at 5000; `hasMore` is ignored ([backtest.service.ts](../../frontend/src/app/services/backtest.service.ts#L114), lines 114–172; BacktestJobService.java:532–573). ## Remaining native M3 blockers

1. Bind the data-reader listing IDs and verify an imported malicious ID cannot alter bars/actions queries (**CRITICAL-1**).
2. Complete cutoff-versus-observation eligibility, precise/unpaid payment metadata and missing-timing rejection, split precision rejection, frozen build/config identity and chronological business events (**HIGH-1/2/3**).
3. Establish concurrent reservation, repeat/queued cancellation, cancellation/publication race, bounded-queue rejection and rollback with deterministic temporary-database tests; do not infer them from 147 passing tests (**HIGH-4**).
4. Load or visibly bound complete candidate/benchmark charts and paged audit tables, suppress stale clear/create responses, restore cost defaults and contract accuracy (**HIGH-5/MEDIUM-4**).
5. Correct the first-execution funding/day count and annual-period labels, enforce exact export bounds, and validate/preserve existing rows on V5 upgrade with actual listing integrity (**MEDIUM-1/2/3**).
6. Reconcile the report under the original IDs and supply repeatable native browser/download evidence. The named recording/ZIP were not available to this review (**MEDIUM-5**).

The currently passing native suites and build are valuable regression checks, but the verified defects above prevent an M3 closeout recommendation. Docker stays deferred; M4 was neither implemented nor reviewed.
